# Cascade 编排

只在用户显式调用 `/cascade` 后生效，覆盖当前任务及其后续跟进，任务完成后结束；用户可提前停用。不修改全局指令、Agent 配置或模型默认值。

## 角色

| 层级 | 执行者 | 职责 |
|---|---|---|
| 主 Agent | 当前会话（Opus） | 持有目标和范围，一次拆解，派发 planner，跨工作块集成验收，向用户交付 |
| 中间层 | `cascade-planner`（Sonnet） | 二次拆解工作块，派发 worker，验收叶子，汇报 |
| 执行层 | `cascade-worker`（Haiku） | 实施单个叶子并自验，汇报 |

worker 没有 Agent 工具，层级最多两级。任何一层发现需要扩大范围、新增决策或缺少输入时，都停止并回报上一层，由上一层调整拆解；不越级、不自行扩展。

调度前确认 `cascade-planner` 与 `cascade-worker` 已注册（Agent 工具的可用类型中能看到）。未注册时说明需要重启会话加载，不用其他模型冒充。

## 选择层级

先只读检查目标、现有改动、仓库边界、运行入口和依赖，再做一次拆解，按结果选择：

- **三层**：拆出 ≥2 个相互独立的工作块，且每块还能再拆成 ≥2 个叶子 → 每块派一个 planner。
- **两层**：工作块不需要再拆 → 主 Agent 直接把叶子派给 `cascade-worker`，自己承担 planner 的验收职责。
- **单层**：任务很小，拆解本身不划算 → 主 Agent 直接完成，并告知用户未启用编排。

## 一次拆解

工作块按可独立验收的产出物划分。代码任务按文件所有权分区：同一文件只归一个工作块；必须由多块修改的文件，放进同一块或安排为串行依赖。每个工作块写清：

```text
工作块 Pn
子目标：本块要产生的结果
范围：允许处理的路径、接口和行为；明确不包含的范围
文件所有权：本块可写的文件
前置依赖：必须先完成的工作块或输入
块级验收：要运行的命令、要检查的行为和通过条件
并发上限：本块同时运行的 worker 数（默认 4）
```

派给 planner 的 prompt 要自包含（它看不到当前上下文），并附带用户已给出的授权边界。任务树默认保留在会话内；项目已有任务记录时沿用既有位置。

## 调度

- 文件所有权不重叠的工作块并行派发，默认最多同时 3 个 planner；用户调用时指定的上限优先。
- 有依赖的工作块等上游验收通过后再派发。
- 跨块集成写成显式工作块或叶子，依赖全部上游完成后执行。
- 改派或重新拆分正在执行的工作块前，先确认原 planner 已结束，再收回并重新分配文件所有权。
- 长任务用后台运行派发，完成通知回来前可以只读检查 diff 和日志；不把没有新消息当作完成。

## 验收

- planner 的"完成"汇报不等于验收。主 Agent 核对实际 diff 和工作区状态，亲自运行块级验收和必要的集成验证。
- 失败时保留失败命令和原始输出，在任务树中增加修复工作块或叶子并派发；不降低断言、不删检查、不把失败写成通过。
- planner 回报"需要上层决定的事项"时，主 Agent 在授权范围内决定；超出授权的交给用户。
- 提交、推送、发布等外部操作仍须在用户已有授权范围内，委派不等于授权。

## 完成与交付

所有工作块的块级验收和必要的集成验证都由主 Agent 核对通过后，才报告完成。有阻塞时只能报告部分完成并说明阻塞。

最终回报包含：采用的层级（三层 / 两层 / 单层）、各工作块结果、主 Agent 实际运行的验证及结果、未完成项和需要用户决定的事项。区分"下层完成回报"和"主 Agent 验收"，不把前者写成后者。

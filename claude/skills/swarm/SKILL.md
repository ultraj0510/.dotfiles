# Swarm 编排

只在用户显式调用 `/swarm` 后生效，覆盖当前任务及其后续跟进，任务完成后结束；用户可提前停用。不修改全局指令、Agent 配置或模型默认值。

## 角色

| 角色 | 执行者 | 职责 |
|---|---|---|
| 主 Agent | 当前会话 | 持有目标和范围，一次拆成扁平任务，派发、验收、集成、向用户交付 |
| worker | `worker`（固定 Haiku 5.5） | 实施单个任务并自验，汇报 |

只有这两层。worker 没有 Agent 工具，不能再派发。worker 发现需要扩大范围、新增决策或缺少输入时，停止并回报，由主 Agent 调整。

调度前确认 `worker` 已注册（Agent 工具的可用类型中能看到）。未注册时说明需要重启会话加载，不用其他类型冒充。

## 拆解

先只读检查目标、现有改动、仓库边界和运行入口，再拆成扁平任务列表。每个任务互相独立，写清：

```text
任务 Tn
目标/范围：要产生的可观察结果；明确不包含的范围
输入：已确认的文件、接口、日志
文件所有权：本任务可写的文件
前置依赖：必须先完成的任务（尽量为空）
验收：要运行的命令、要检查的行为和通过条件
```

- 每个文件只归一个任务。必须由多个任务修改的文件，合并成一个任务，或用前置依赖安排串行。
- worker 固定为 Haiku，拆任务时把每个任务切到 Haiku 能一次完成并自验的大小；需要判断力的部分由主 Agent 自己做。
- 任务很小或无法拆成 ≥2 个独立任务时，主 Agent 直接完成，并告知用户未启用蜂群。
- 跨任务集成写成显式任务，依赖全部上游完成后执行。

派给 worker 的 prompt 要自包含（它看不到当前上下文），并附带用户已给出的授权边界。任务列表默认保留在会话内；项目已有任务记录时沿用既有位置。

## 调度

- 并发上限默认 6 个 worker；用户调用时指定的上限优先。
- 一次拆好全部任务，按上限推进：一个完成并通过验收，就补派下一个无未满足依赖的任务。
- 允许根据结果追加任务，追加时重新检查文件所有权，仍然一文件一写者。
- 改派或重新拆分正在执行的任务前，先确认原 worker 已结束，再重新分配文件所有权。
- 用后台运行派发；完成通知回来前可以只读检查 diff 和日志，不把没有新消息当作完成。

## 验收

- worker 的"完成"汇报不等于验收。主 Agent 逐个核对实际 diff 和工作区状态，亲自运行任务级验收命令。
- 失败时保留失败命令和原始输出，追加修复任务并派发；同一问题连续两次修复失败，主 Agent 自己接手或回报用户。不降低断言、不删检查、不把失败写成通过。
- 所有任务通过后，运行必要的集成验证。
- 提交、推送、发布等外部操作仍须在用户已有授权范围内，委派不等于授权。

## 完成与交付

所有任务的验收和必要的集成验证都由主 Agent 核对通过后，才报告完成。有阻塞时只能报告部分完成并说明阻塞。

最终回报包含：任务数与并发情况、各任务结果、主 Agent 实际运行的验证及结果、未完成项和需要用户决定的事项。区分"worker 完成回报"和"主 Agent 验收"，不把前者写成后者。

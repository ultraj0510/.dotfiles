# Using Simplify

协议版本：`0.3.0`。本文件只决定适用性和模式；[simplify](../simplify/SKILL.md) 负责审查与收敛。AGENTS.md 只保留入口，不复制协议。

## 适用性

在主要实现完成、准备交付时检查本任务产生的行为改动，包括已提交但尚未验收的改动，不仅看工作树是否干净。

以下跳过：没有行为改动；只有普通文档、注释、格式化；只读 reviewer 无实现责任；用户明确要求立即停止。Agent 指令虽然是 Markdown，仍属于行为改动。适用性有争议时按内容判断，不按文件后缀。

跳过只需在相关收尾中简述原因，不在普通问答中播报。`no cleanup needed` 是实际审查后的结果，不是跳过理由。

## 选择模式

依次判断 skip、Strict、Lite，其他为 Standard：

- **Strict**：权限或安全边界、公开协议、持久化迁移、生产运行行为、全局 Agent 授权与完成规则等发生实质变化，或多个调用面存在显著耦合风险。
- **Lite**：影响局部、低风险、可回退，受影响路径清晰，已有简单验证足够。
- **Standard**：其余常规功能、修复和重构。

文件数量、配置或 manifest 后缀、增加正常测试只提示检查风险，不单独强制升级。依赖变更根据运行影响判断；共享模块根据实际调用面判断。说明一项实际模式依据即可。

## 路由

选择任务类型 `feature`、`refactor` 或 `bugfix`；调试、测试、架构和指令修改按其实际目的归类。将模式、类型、任务 diff 范围和风险依据交给 `simplify`，无需用户确认。

直接调用 simplify 缺少上述参数时，自行读取本文件补全一次，不来回退回或停止询问用户。Skill 无法读取时完成等价的范围、正确性、复杂度和验证自审并披露降级；存在具体未解决风险时才阻塞完成。

当前 diff 审查过且此后未变化，复用其证据；修正只复查受影响内容，不重启整套流程。只读 reviewer 不递归触发收尾审查。

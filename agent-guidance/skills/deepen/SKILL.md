# Deepen

对用户给出的任务得到更深层版本。更深指方法、材料和验证更专业，范围和篇幅不因此扩大。

## 确定对象

用户在 deepen 调用（Claude 用 `/deepen`，Codex 用 `$deepen`）后提供内容时，以该内容为要加深的任务或 prompt。没有内容时，取本会话中最近一条可识别的用户任务请求，跳过调用本技能本身的消息。找不到时，只问一句要加深哪个任务。

## 回答四个问题

先逐一写出以下四个问题的答案。每个答案针对当前任务，保持简短具体。

1. 这个领域的顶尖专业人士在这里会做什么？只写用户没有要求、但完成同一目标时专业人士一定会做的事。
2. 他们会从什么最原始的材料开始？指一手数据、原始文件、原始来源，而非他人整理的摘要。
3. 他们会用什么具体方法和工具？写出名称及用途，避免“深入分析”这类泛称。
4. 除了你和用户之外，什么能证明结果是对的？给出外部可检验的依据，例如实测、真实数据、独立来源、可复现的运行结果或适用的领域标准。自己的自查和用户的主观判断不算。

第 4 问没有外部依据时，明确写“此处没有外部验证手段”，并在重写后的 prompt 中注明哪些结论只能标为未验证。

## 重写 prompt

按四个答案生成一段可直接使用的 prompt，纳入专业做法、原始材料、具体方法和工具、外部验证。不添加四个答案之外的新范围。

保留原任务的目标、对象、交付物、限制及授权边界。专业做法只服务于原目标，必要时用更可靠的方法替换原做法，不额外增加项目、系统或研究分支。

方法与工具须适合任务。未确认可用的工具写成执行时需要核实的条件，不声称工具、数据或验证结果已经存在。只重写时，描述需要取得的材料和证据，不提前采集数据或运行改写后的任务。

涉及下单、发布、删除、发送等真实操作时，保持已有授权范围，只加深准备、核对和验证部分。改写文本本身不授予新的操作权限。

## 交付与执行边界

依次交付四个简短答案、重写后的 prompt，以及一句说明它比原版深在哪里。遵循当前会话的输出格式要求。需要方便复制时，将重写后的 prompt 放入单独的代码块。

默认到此结束。只有用户明确要求“重写后直接做”或同等含义时，才在重写后执行，并继续遵守当前环境的权限与工具边界。

# Swarm 共通规则

本文件是 Claude `/swarm` 与 Codex `$swarm` 共用的唯一编排规范。每个宿主入口必须先读取 `~/.dotfiles/agent-guidance/swarm.md`，将 `~` 解析为用户主目录。若文件缺失或无法读取，停止委派并报告阻塞。

显式调用只覆盖当前任务及其后续跟进，到任务完成或用户明确停用为止。用户可直接调用，也可由上级在任务委派中明确指定使用 swarm。宿主的全局指令可声明 swarm 默认开启。启用后，该宿主的每个任务都按 swarm 执行，直到用户在当前会话明确停用。

## 角色与权限

- 主 Agent 持有目标和范围，做只读调查、拆解、派发、协调、只读证据核验和最终验收。
- worker 承担所有实施，包括文件写入、测试运行、故障诊断与修复、集成、实施自验、提交和发布。它只在用户授权的范围内行动。
- 主 Agent 可以运行验收测试和只读核验。验收可以生成测试产物，但不能改业务文件、部署或迁移。
- 用户明确允许主 Agent 接手时，主 Agent 才能实施。显式调用 `/swarm` 或 `$swarm` 后，单个小任务也交给 worker。
- 收到明确 swarm 委派的执行者，在分配范围内承担该任务的主 Agent 职责，直接派发给一层 worker，并向上级回报验收结果。末级 worker 只执行收到的任务。缺少必要输入或需要新决策时，向直接派发者报告。
- 委派不扩大远程权限。提交、发布或其他外部操作须已有相应授权；没有授权时完成可安全准备的部分，并在边界说明阻塞。

## 固定模型

只按当前宿主入口声明的固定模型派发，并在派发前确认模型可用。该模型不可用时暂停并等待用户决定，不替换为其他模型。宿主入口规定该模型允许使用的角色和路由。

## 拆解与调度

主 Agent 先只读确认目标、现状、依赖和边界，再建立扁平任务列表。复杂任务可按结果分组，每项直接交给末级 worker。每个派发包写清目标、范围、已确认输入、唯一文件所有者、前置依赖、用户授权、验收、所需证据和末级 worker 的职责。一个文件同一时间只有一个写者；并行任务的文件和接口必须互不冲突。必须进行集成时，建立依赖上游完成的显式集成任务并指定唯一写者。

验收写成可运行的判据：每项任务给出具体命令、预期输出或可核对的状态，由 worker 之外的东西（测试、构建、复现、度量）判定通过，而不是 worker 或主 Agent 的文字判断。判据无法写出时，先建立只读调查任务去找到它。

并行写入的 worker 优先使用互相隔离的工作区。Git 仓库用各自的 worktree 或分支，非 Git 目录用各自的副本，使并行修改不会互相覆盖。隔离不取代唯一文件所有者：集成仍由依赖上游的显式集成任务和唯一写者完成。创建隔离工作区前，先确认目标路径、现有改动和分支状态，并保留用户及其他 Agent 的修改。

默认最多并发 6 个 worker。派发前估算 worker 总数和长时间运行的任务数。规模明显超出用户预期的额度或时间时，先向用户说明规模再派发。worker 完成回报后即收尾，不保持空转；有新依赖任务时再派发。用户指定的上限、宿主实时容量、工具并行度和任务独立性共同决定实际并发。一个 worker 完成后，按依赖补派下一项，并优先复用可用 worker。改派或集成接手前，先确认原 worker 已停止写入，再收回和重新分配文件所有权。

主 Agent 维护一份进度看板，记录每项任务的状态、所有者、依赖、最新证据和阻塞。看板放在会话 scratchpad，worker 之间不互相通信，也不互相委派。每到里程碑、失败或阻塞，主 Agent 向用户简短报告，使用户能实时跟踪。用户中途纠正目标或范围时，主 Agent 先判断受影响的任务，只暂停和改派这些任务，并向其余 worker 说明不变。

长任务开始前设定可观察里程碑和按复杂度选择的最长无进展窗口。worker 到达里程碑时报告产物和验证证据。窗口到期后，主 Agent 先只读检查运行状态、diff、日志、测试输出、提交和相关外部状态，再要求 worker 汇报当前阶段、产物、错误和下一步。若仍无回应或进展，保存证据后中断，并在确认旧 worker 停止写入后改派。

## 验证、修复与独立审阅

worker 运行实施所需的验证并修复失败。主 Agent 根据实际 diff 和证据做只读验收，可运行验收测试。失败时保留原始命令和输出，不降低断言或删除有效检查，并委派诊断、修复和重跑。同一问题连续两次修复失败后，主 Agent 重新分析和拆解，再派给 worker；不得自动接手实施。

验证强度按风险分三层：

- 低风险局部改动：worker 自验加主 Agent 只读验收即可。
- 业务逻辑变更：另派一名对抗式验证 worker。它的任务是推翻结果，不是确认结果：独立运行测试、构造反例和边界输入、检查相邻功能是否被破坏。它只读，不能是实施作者，不能修改被审内容，也不能看实施者的自验结论，以免被带偏。
- 权限边界、公共接口、数据迁移或生产行为变更：在对抗式验证之外，再做独立只读审阅，覆盖兼容、安全和回滚证据。

验证者找到的问题带命令和原始输出回报主 Agent，由主 Agent 派发修复和重跑，直到判据通过。主 Agent 根据实际 diff、实施验证和验证者结果做最终验收，并如实报告验证者未能覆盖的部分。

## 回报与完成

worker 的完成回报、主 Agent 的只读验收、发布后的外部状态核验是三种不同证据，分别报告。worker 完成不等于主 Agent 验收通过；本地验收不等于发布已核验。

简单任务报告实际 worker 和模型、改动结果、验证命令与证据、主 Agent 验收状态。复杂任务按规模报告任务数、并发情况、依赖与集成、对抗式验证与独立审阅、worker 回报、主 Agent 验收和发布后状态。必要工作或证据受阻时，只报告部分完成和具体阻塞。

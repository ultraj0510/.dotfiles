# Swarm 共通规则

本文件是 Claude `/swarm` 与 Codex `$swarm` 共用的唯一编排规范。每个宿主入口必须先读取 `~/.dotfiles/agent-guidance/swarm.md`，将 `~` 解析为用户主目录。若文件缺失或无法读取，停止委派并报告阻塞。

显式调用只覆盖当前任务及其后续跟进，到任务完成或用户明确停用为止；新任务不继承此模式。它不改变全局指令、Agent 配置或默认模型。

## 角色与权限

- 主 Agent 持有目标和范围，做只读调查、拆解、派发、协调、只读证据核验和最终验收。
- worker 承担所有实施，包括文件写入、测试运行、故障诊断与修复、集成、实施自验、提交和发布。它只在用户授权的范围内行动。
- 主 Agent 可以运行验收测试和只读核验。验收可以生成测试产物，但不能改业务文件、部署或迁移。
- 用户明确允许主 Agent 接手时，主 Agent 才能实施。显式调用 `/swarm` 或 `$swarm` 后，单个小任务也交给 worker。
- worker 只执行派发给它的任务，不能再派发或扩大范围。缺少输入、需要额外文件或需要新决策时，先停止并报告主 Agent。
- 委派不扩大远程权限。提交、发布或其他外部操作须已有相应授权；没有授权时完成可安全准备的部分，并在边界说明阻塞。

## 固定模型

只按当前宿主入口声明的固定模型派发，并在派发前确认模型可用。该模型不可用时暂停并等待用户决定，不替换为其他模型。宿主入口规定该模型允许使用的角色和路由。

## 拆解与调度

主 Agent 先只读确认目标、现状、依赖和边界，再建立扁平任务列表。复杂任务可按结果分组，但每项都直接交给 worker，不能形成 worker 之间的委派层。每个派发包必须自包含，因为 worker 可能看不到当前会话。写清目标、范围、已确认输入、唯一文件所有者、前置依赖、用户授权、验收、所需证据和不得再委派。一个文件同一时间只有一个写者；并行任务的文件和接口必须互不冲突。必须进行集成时，建立依赖上游完成的显式集成任务并指定唯一写者。

默认最多并发 6 个 worker。用户指定的上限、宿主实时容量、工具并行度和任务独立性共同决定实际并发。一个 worker 完成后，按依赖补派下一项，并优先复用可用 worker。改派或集成接手前，先确认原 worker 已停止写入，再收回和重新分配文件所有权。

长任务开始前设定可观察里程碑和按复杂度选择的最长无进展窗口。worker 到达里程碑时报告产物和验证证据。窗口到期后，主 Agent 先只读检查运行状态、diff、日志、测试输出、提交和相关外部状态，再要求 worker 汇报当前阶段、产物、错误和下一步。若仍无回应或进展，保存证据后中断，并在确认旧 worker 停止写入后改派。

## 验证、修复与独立审阅

worker 运行实施所需的验证并修复失败。主 Agent 根据实际 diff 和证据做只读验收，可运行验收测试。失败时保留原始命令和输出，不降低断言或删除有效检查，并委派诊断、修复和重跑。同一问题连续两次修复失败后，主 Agent 重新分析和拆解，再派给 worker；不得自动接手实施。

权限边界、公共接口、数据迁移或生产行为发生变化时，另派一名 worker 做独立只读审阅。审阅者不能是实施作者，也不能修改被审内容。主 Agent 根据实际 diff、实施验证和审阅结果做最终验收。

## 回报与完成

worker 的完成回报、主 Agent 的只读验收、发布后的外部状态核验是三种不同证据，分别报告。worker 完成不等于主 Agent 验收通过；本地验收不等于发布已核验。

简单任务报告实际 worker 和模型、改动结果、验证命令与证据、主 Agent 验收状态。复杂任务按规模报告任务数、并发情况、依赖与集成、独立审阅、worker 回报、主 Agent 验收和发布后状态。必要工作或证据受阻时，只报告部分完成和具体阻塞。
